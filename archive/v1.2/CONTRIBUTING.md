# 贡献说明

先读[选择规则](docs/selection-policy.md)与[同类比较](docs/comparisons.md)。欢迎有独立价值、证据明确的单项 Skill；不接收合集倾倒、简单改名、仅按热度排名或夸大兼容性的提案。

## 单项提案应包含

- 原始 GitHub 仓库、具体 SKILL.md 目录、完整 Commit、维护/作者依据。
- 许可声明、准确链接及覆盖范围，依赖、服务、字体或第三方资产的独立边界。
- 核心用途、典型场景、推荐原因，以及何时选择它或已有相关条目。
- 环境/工具版本、联网与写入权限、自动安装/更新或数据外发等风险及采用门槛。
- [证据类别](docs/validation.md)：静态、示例、测试源码、评估设计、具体成功记录、本地或客户端测试；没有运行就明确未验证。

平台专项、合理依赖或专有许可不自动排除导航；但受限参考只能原创介绍与原链，不能提供未经授权的提取/安装/执行或再分发方案。不要提交第三方 Skill 源码、脚本、模板、私有审计、原始缓存、业务规则、凭据或个人系统路径。

## 修改数据与文档

以现有 catalog 为基础增量修改，保持 ID 唯一，固定 Skill 与 runtime 版本分开。新增条目同步 README、详情、比较和必要采用/许可说明；新 schema 字段尽量可选，不改写旧条目已确认事实。

检查 JSON/schema、数量、分类、内部链接和实际变更文件；外链注明可靠原始来源，不因整理文档重新执行上游安装器或全量审计。受限参考必须同时使用 reference 与 navigation_scope=restricted_reference，并保留明确的权利限制。

更新提交说明应写清来源/版本差异、验证范围和影响；旧记录留在 Git 历史。许可冲突、隐式环境修改、权限扩大或重大缺陷未解释前暂停采用建议。回滚恢复明确旧提交或单项差异，不清理用户环境，详见[维护规则](docs/selection-policy.md)。

贡献者须有权提交自己的内容；原创导览按本项目 [CC BY 4.0](LICENSE) 发布，边界见[许可说明](LICENSE-NOTICE.md)。该许可不重新授权任何第三方材料；未来可执行代码需另行明确许可证。
