# 选择与长期维护规则

## 选择标准

- 回到原始 Skill 仓库确认维护方、完整 Commit、具体目录和许可；目录热度、Stars 和榜单只作参考。
- 区分 Skill、底层工具、管理器、MCP 服务和框架；一个仓库可包含多个独立 Skill，不能把合集当作一个已验证能力。
- 优先开放格式、明确触发范围、相对资源、最小依赖与可独立使用的单项。
- 核对脚本、资产、依赖的许可和行为；公开可读不等于可自由复制。
- 记录真实测试范围；未知项保留未知，不将所有平台官方机制支持写成实测通过。
- 已有等效能力就参考或复用，不靠重复注册提示词增加数量。

## 分层

精选推荐用于优先考虑；按需使用必须有明确场景且满足门槛；参考资源用于已有能力复用和方法查询。层级不是评分、质量保证或安装承诺。

本目录不引入整套科研环境、强制方法论框架或管理平台作为默认前置条件。不分发专有或再分发权不明确的源码，不把提取文本当作原生 Office 编辑，不自动运行上游安装器。

## 新增与更新

1. 提交一个明确用途的单项，提供原始目录、维护方、完整 Commit 与许可链接。
2. 说明和现有条目的不同价值、最小依赖、联网/写入权限及预期使用范围。
3. 审阅必要源码与相对资源，核对工具版本及第三方权利，不复制无授权素材。
4. 有本地验证就记录合成样例与实际值；没有就标记未验证。不得虚构跨平台结果。
5. 同步 README 分类表、docs/skills.md、catalog.json 及 reviewed_at；必要时更新 schema_version。
6. 复核链接、唯一 ID、完整 Commit、许可证范围与敏感信息，人工审核后再合并。

更新时新旧版本分开审阅，不盲目追新。重大许可或依赖变化优先暂停推荐，不用自动更新掩盖问题。撤下条目应记录公开原因与旧基线，不发布私有审计、内部规则或个人运行环境。

## 结构化目录

catalog.json 是未来网站可使用的数据源；catalog.schema.json 描述结构，不是数据库或安装系统。id 应稳定且唯一，upstream.commit 使用完整 40 位 SHA；Skill 与 runtime_candidates 分别固定。项目原创内容许可证状态与第三方 license 字段相互独立。

此仓库没有网站、自动安装任务或后台同步服务；未来是否增加属于单独决策。
